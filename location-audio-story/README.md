# 🎧 まち歩き音声ガイド / Location Audio Story

古い街の物語を、**その場所に着いたら自動で音声再生**する Web アプリです。
iPhone の Safari だけで動きます（App Store 申請・Mac・Xcode 不要）。

A web app that automatically plays an audio story when you arrive at a spot.
Runs in iPhone Safari — no App Store, no native app needed.

## なぜブラウザ版か / Why browser-based?

| | ブラウザ (このアプリ) | iPhoneネイティブアプリ |
|---|---|---|
| 開発・配布 | HTML 1ファイル、URLを共有するだけ | Mac + Xcode + 開発者登録($99/年) + 審査 |
| GPS | Geolocation API (精度はネイティブとほぼ同等) | Core Location |
| バックグラウンド動作 | ❌ 画面ON中のみ (Wake Lockで画面を維持) | ✅ 画面OFFでも動く |
| 音声 | Web Speech API 合成音声 / mp3 | 同等 |

「まず動くものを試す」段階ではブラウザ版が圧倒的に楽です。
画面OFFのまま歩きたい・Bluetoothビーコン対応をしたい、となった段階でネイティブ化（後述）を検討すれば十分です。

## 使い方 / How to use

1. このフォルダを **GitHub Pages** で公開する（位置情報は HTTPS 必須のため）:
   - リポジトリの Settings → Pages → Branch を選んで保存
   - `https://<user>.github.io/<repo>/location-audio-story/` を iPhone で開く
2. 位置情報の許可は「**Appの使用中は許可**」+「**正確な位置情報: ON**」を選ぶ
3. 「▶ ガイド開始」を押す（← この操作で iOS の音声再生ロックも解除されます）
4. スポットに近づくと自動で解説が読み上げられます

- スポットは「＋現在地に追加」ボタン、または「スポット編集(JSON)」で登録
- データは端末の localStorage に保存。外部送信は一切なし
- 「シミュレーション」で室内でも動作確認できます

### スポット定義 / Spot format

```json
{
  "name": "日本橋 (麒麟像)",
  "lat": 35.684056,
  "lon": 139.774501,
  "radius": 35,
  "text": "ここは日本橋。江戸時代、五街道の起点と…",
  "audioUrl": "https://example.com/nihonbashi.mp3",
  "lang": "ja-JP"
}
```

`audioUrl` があれば録音ファイルを再生、なければ `text` を合成音声で読み上げます。

## ビル街のGPS誤差への対策 / Handling urban-canyon GPS error

ビルの谷間では反射波（マルチパス）で GPS が 30〜100m 飛ぶことがあります。
このアプリは「単純に円に入ったら再生」ではなく、**4段構えのフィルタ**で誤発動を防いでいます（すべて実装済み・設定画面で調整可）:

1. **精度フィルタ** — OS が報告する精度が閾値（既定 50m）より悪い測位は捨てる
2. **ジャンプ除去** — 前回位置から時速40km超相当の「瞬間移動」は反射波とみなして捨てる
3. **平滑化** — 精度に応じた重み付き指数平滑。精度の良い測位は大きく、悪い測位は少しだけ位置を動かす
4. **ヒステリシス + 滞留判定** — 「入る判定円」より「出る判定円」を大きくとり（半径×1.6+15m）、さらに連続 N 回（既定3回）円内で測位できて初めて発動。境界でのチャタリング（入った/出たの連打）を防ぐ
5. **クールダウン** — 一度再生したスポットは既定30分間は再発動しない（周囲をぐるぐる歩いても繰り返さない）

さらに実運用のコツ:

- **発動半径を欲張って小さくしない**。ビル街なら 30〜50m が現実的。「その建物の前ピンポイント」は GPS では原理的に無理
- スポットの登録座標は**道路側（歩く場所）に寄せる**と体感精度が上がる
- iPhone 側は「正確な位置情報」を ON に。Wi-Fi を ON にしておくと Wi-Fi 測位が併用されて都市部では精度が上がる

### それでも足りない場合の発展手段 / If GPS is still not enough

| 手段 | 精度 | コスト・備考 |
|---|---|---|
| **BLE ビーコン** (iBeacon) | 数m | スポットに電池式ビーコン(1個2千円程度)を設置。ネイティブアプリ必須。屋内・地下・ビル密集地の決定版 |
| **経路スナップ (map matching)** | 向上 | 「決まった散策コース」なら、測位をコース線上に射影して進行距離で発動。コースが決まっているツアーに最適 |
| **QRコード / NFCタグ** | 完全 | 現地の看板にQRを貼り、読むと該当音声ページへ。GPS不要で確実。廉価な併用策としておすすめ |
| **方位・歩数センサ融合 (PDR)** | 向上 | ジャイロ+歩数で GPS の谷間を補間。ネイティブ実装向き |
| **Wi-Fi/5G測位サービス** | 10-30m | Google Fused Location 等。iOSでは標準の測位に既に統合されている |

現実的な組み合わせは **「GPS + 本アプリのフィルタ」を基本に、GPSが死ぬ場所（地下街・高層ビル直下）だけ QR コードを併設** が最も安く確実です。

## 高さ・階数の認識 / Floor & height recognition

まず前提を正直に: **フロア間隔は約3.5m、GPSの高度誤差は±10〜50m** です。
つまり「何階にいるか」を GPS だけで当てるのは原理的に不可能です。手段は3段階あります。

### ① このアプリで出来ること (実装済み)

スポットに `alt`(高度m) と `altTol`(許容差m, 既定20) を付けると、**水平位置が同じでも高度が大きく違う場合は発動しない** 高度ゲートが働きます:

```json
{ "name": "スカイデッキ", "lat": 35.68, "lon": 139.76, "alt": 270, "altTol": 30,
  "text": "地上230メートルの展望台から…" }
```

- 有効なのは **数十m級の高低差**: 展望台 vs 地上、橋の上 vs 川沿いの遊歩道、崖の上下 など
- 「2階と3階の区別」には**使えません**（誤差がフロア間隔より大きいため）
- ⚠️ GPS高度は「楕円体高」で、東京では海抜より約40m大きい値が出ます。数値を手打ちせず、**その場所で「＋現在地に追加」を押して自動記録**すれば同じ基準系で比較されるため、このズレは問題になりません
- 高度の測位精度が悪い時 (>30m) はゲートを自動で無効化し、誤ブロックを防ぎます

### ② 本当に階数を当てたい場合 → ネイティブアプリ + 気圧計

iPhone には気圧計が内蔵されており、**相対高度を ±0.5〜1m** で測れます。フロア判定の本命はこれです。ただし **Safari からは気圧計にアクセスできない** ため、ネイティブアプリ (または Capacitor ラップ + プラグイン) が必要です:

- `CMAltimeter.startRelativeAltitudeUpdates` — 気圧による相対高度。階段/エレベーター1フロア分の上下がはっきり分かる
- `CMAbsoluteAltitudeData` (iOS 15+) — 気圧+GPS+地図を融合した海抜高度
- `CLLocation.floor` — 屋内測位対応済みの建物(大型駅・空港・一部商業施設)では階数そのものが返る
- 注意: 気圧は天気で変わるため、絶対値でなく「地上階を基準にした相対変化」で判定するのが定石

### ③ アプリを問わず確実な方法 → 階ごとのビーコン / QR

- **iBeacon をフロアごとに設置** — 電波は床・天井をあまり抜けないため、実質そのまま階数判定になる (ネイティブ必須)
- **階ごとの QR コード** — ブラウザのままで使える唯一の確実な方法。エレベーターホールに掲示

推奨: 屋外の街歩きは①のまま、建物内のフロア別コンテンツが本当に必要になった時点で Capacitor ラップ + 気圧計プラグイン (②) に進むのが最小コストです。

## ネイティブ化する場合 / Going native later

画面OFFでの案内・iBeacon 対応が必要になったら:

- **Swift + Core Location の Region Monitoring**: OSレベルのジオフェンス（半径100m〜、最大20領域）。アプリが起動していなくても発火
- もしくは **Capacitor** でこの HTML をそのままラップし、`@capacitor/geolocation` + background mode を足す方法が最短
